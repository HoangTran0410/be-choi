# Bé Chơi v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a PWA of 12 offline toddler mini-games (age 2+) with a shared shell, Vietnamese voice, and mobile/tablet-first touch UI.

**Architecture:** Vite + strict TypeScript, no UI framework. A hash router mounts either the home grid or a game shell; the shell lazy-loads one `GameModule` and hands it a `GameContext` (stage element, audio synth, speech, celebrate, hint scheduler, star storage, cleanup). Each game is a folder with `meta.ts` (static, imported by the registry), `logic.ts` (pure, unit-tested), `index.ts` (DOM), `style.css`.

**Tech Stack:** Vite 6, TypeScript 5 strict, vite-plugin-pwa (Workbox generateSW), Vitest + jsdom, Web Audio API, Web Speech API, Pointer Events, Canvas 2D. Zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-02-be-choi-design.md`

## Global Constraints

- Node 22, npm (package-lock committed). No runtime dependencies.
- All user-visible text is Vietnamese. Games must be playable without reading.
- No fail state, no timer, no score text in any game. Wrong action = gentle `boing` + spring back, never a sad sound.
- Every tappable thing a child uses is at least `var(--tap)` = `clamp(72px, 14vmin, 140px)` on its short side.
- Every game must work in portrait (390×844) and landscape (1024×768) without scrolling.
- Stage has `touch-action: none`; use Pointer Events only (no mouse/touch event handlers).
- Game folders never import from other game folders. Shared helpers live in `src/core`.
- Commit after each task with `git commit`, message ending in the `Claude-Session:` trailer given in the session.

```ts
export interface AudioEngine {
  readonly enabled: boolean;
  unlock(): void;                 // create/resume AudioContext (call on first pointerdown)
  setEnabled(on: boolean): void;
  pop(pitch?: number): void;      // 60 ms sine blip 600 Hz × pitch → fast decay
  ding(): void;                   // 880 → 1320 Hz two-tone, 250 ms
  boing(): void;                  // 300 → 120 Hz sweep, 250 ms, soft
  chomp(): void;                  // filtered noise burst 120 ms
  tick(): void;                   // 20 ms click
  jingle(): void;                 // C5 E5 G5 C6 arpeggio, 80 ms apart
  note(freq: number, dur?: number): void; // triangle wave w/ ADSR, default 500 ms
}
export function createAudio(): AudioEngine;

export interface Speech {
  warm(): void;                                  // speak '' to satisfy iOS gesture requirement
  setEnabled(on: boolean): void;
  available(): boolean;                          // vi voice found
  speak(text: string, opts?: { interrupt?: boolean }): void; // interrupt defaults true
  cancel(): void;
}
export function createSpeech(synth?: SpeechSynthesis | null): Speech;  // default window.speechSynthesis ?? null
```

Audio implementation notes: `AudioContext` created lazily in `unlock()`; every method returns early if `!ctx || !enabled`; master `GainNode` 0.5; each sound = `OscillatorNode` (or noise `AudioBufferSourceNode` for chomp) → `GainNode` with `setValueAtTime`/`exponentialRampToValueAtTime` envelope → master. Guard with `try/catch` so a closed context never throws.

Speech implementation notes: pick voice with `lang.toLowerCase().startsWith('vi')`, re-check on `voiceschanged`. `speak` builds `SpeechSynthesisUtterance`, `lang='vi-VN'`, `rate=0.95`, `pitch=1.1`; if `interrupt` → `cancel()` first. If no vi voice or disabled → no-op.

```ts
// drag.ts
export interface Pt { x: number; y: number }
export interface Target { id: string; rect: DOMRectReadOnly | { left: number; top: number; width: number; height: number } }
export function hitTest(p: Pt, targets: readonly Target[], tolerance = 0): string | null; // first match, rect grown by tolerance on every side
export interface DragOptions {
  onStart?(el: HTMLElement): void;
  onMove?(el: HTMLElement, p: Pt): void;
  /** Return true to accept (element keeps its offset; caller usually re-parents/animates it), false to spring back. */
  onDrop(el: HTMLElement, p: Pt): boolean | Promise<boolean>;
}
export function makeDraggable(el: HTMLElement, opts: DragOptions): () => void; // dispose
export function centerOf(el: Element): Pt;   // from getBoundingClientRect

// hold.ts
export function onHold(el: HTMLElement, ms: number, cb: () => void): () => void; // dispose
// hint.ts
export function createHint(): HintScheduler;   // from types.ts
```

`makeDraggable` behaviour: on `pointerdown` (primary button only, ignore if already dragging) → `setPointerCapture`, add `.dragging`, remove `.spring-back`, remember start client point and current translate (`el.dataset.dx/dy`, default 0). On `pointermove` → set `el.style.transform = translate(dx,dy)` where d = start offset + pointer delta; call `onMove`. On `pointerup` → release capture, remove `.dragging`, call `onDrop(el, {clientX, clientY})`; if result is false → add `.spring-back`, set transform back to the pre-drag offset. On `pointercancel` → same as false drop. Dispose removes all listeners.

`onHold` behaviour: on `pointerdown` → append `<span class="hold-ring">` if absent, start `requestAnimationFrame` loop setting `--hold-progress` (0→1 over `ms`) on the ring; when elapsed ≥ ms → remove ring, call `cb()` once, and ignore the following `click`. On `pointerup`/`pointercancel`/`pointerleave` before ms → remove ring, cancel. Use `performance.now()` for elapsed so fake timers work with `vi.useFakeTimers({ toFake: ['setTimeout','requestAnimationFrame','performance'] })`. Simplest robust approach: use `setTimeout(ms)` for the trigger and rAF only for the visual ring.

`createHint` behaviour: `arm(fn, ms=6000)` stores fn+ms, starts a `setTimeout`; when it fires → `fn()` then re-arms with the same fn/ms (repeats until `clear`). `touch()` restarts the timer if armed. `clear()` cancels and forgets fn.
